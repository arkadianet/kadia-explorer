# Explorer Frontend (explorer.kadia.io) — Design

Date: 2026-09-06. Status: draft for review. Companion to `2026-09-05-ergo-explorer-design.md`.

## 1. Goal

A new, from-scratch web UI for the standalone Ergo explorer, served at https://explorer.kadia.io
by Caddy from static files, consuming the explorer's `/v1` JSON API. It must feel instant, show
trustworthy numbers, find anything pasted into search, and surface the storage-rent views no other
explorer offers.

Non-goals for phase 1: token/template/holder pages (Plan 2 API), live WebSocket updates, mempool,
analytics charts (Plan 3 API). The design system and page shell are built so those become new pages
only.

## 2. Decisions

| Decision | Choice | Why |
|---|---|---|
| Stack | **SvelteKit 2 + Svelte 5, `adapter-static` (SPA fallback), TypeScript, Vite** | Smallest bundle for a data-dense app, first-class reactivity for live views later, static deploy. |
| Styling | Hand-written CSS with design tokens (custom properties); no CSS framework | Full control of density and theming; no unused utility bloat. |
| Data layer | Thin typed fetch client (`src/lib/api/`) generated by hand from the Rust DTOs; TanStack Query (svelte) for caching/prefetch | Cache, dedupe and prefetch-on-hover with little code. |
| Routing | SvelteKit file routes; entity permalinks mirror the API | Shareable URLs, back/forward correctness. |
| Theme | Dark-first with light theme; `prefers-color-scheme` default, manual toggle persisted in localStorage | Operators and traders mostly run dark; light kept for accessibility. |
| Deploy | `npm run build` → `build/` rsynced to Nuremberg `/var/www/explorer`; Caddy serves `/` with SPA fallback to `index.html`, `/v1/*` proxied | Zero server-side moving parts. |
| Repo location | `frontend/` directory inside the `ergo-explorer` repo | One repo, one version; API and UI change together. |
| Testing | Vitest unit tests for formatters/search-classifier/API mappers; Playwright smoke for each route against a mock API (MSW) | Fast, deterministic; no dependence on a synced node in CI. |

## 3. Information architecture (phase 1 routes)

| Route | Data | Purpose |
|---|---|---|
| `/` | `/v1/status`, `/v1/blocks?limit=10`, `/v1/txs?limit=10`, `/v1/rent/upcoming?blocks=720&limit=5` | Home: indexed height + lag badge, latest blocks and txs, "rent maturing soon" teaser, search. |
| `/blocks` | `/v1/blocks` (cursor) | Infinite list: height, age, txs, size, reward, miner. |
| `/blocks/[id]` | `/v1/blocks/{id}`, `/v1/blocks/{id}/txs` | Header facts, prev/next navigation, tx list with fee/value. |
| `/txs` | `/v1/txs` (cursor) | Infinite list newest first. |
| `/tx/[id]` | `/v1/txs/{id}` | Inputs → outputs flow, fee, data inputs, per-box value/tokens/registers (decoded), rent status per output. |
| `/box/[id]` | `/v1/boxes/{id}` | Full box: value, address, ergo tree (hex + template hash), tokens, registers, spent-by link, rent panel (maturity height, due, claimable). |
| `/address/[addr]` | `/v1/addresses/{addr}`, `/txs`, `/boxes?unspent=`, `/rent` | Balance + tokens, counts, tabs: Transactions / Unspent boxes / All boxes / Rent (boxes sorted by maturity with "claimable in N blocks"). |
| `/richlist` | `/v1/richlist` (cursor) | Rank, address, balance, share of circulating (client-computed from emission at tip). |
| `/rent` | `/v1/rent/upcoming`, `/v1/rent/eligible` | Two tabs: "Maturing in next N blocks" (N selector 72/720/2160) and "Eligible now"; each row = box value, due rent, address, maturity height. |
| `/search?q=` | `/v1/search` | Resolves and redirects; shows "not found" with hints. |
| `/status` | `/v1/status` | Node/indexer health, lag, mode, source; link to raw API. |

Route params accept height or id for blocks; the search classifier (client) decides kind before
calling `/v1/search`: decimal → height; 64-hex → try block/tx/box via API; base58 starting 9/3/2/8 →
address; else "no match".

## 4. Layout and design system

- **Shell**: top bar (logo "kadia explorer", global search, theme toggle, indexed-height/lag badge that
  turns amber when lag > 3 and red when `halted`); left rail on ≥1024px with Blocks / Txs / Addresses
  (rich list) / Rent / Status; bottom nav on mobile. Content max-width 1280px.
- **Tokens** (`src/lib/styles/tokens.css`): `--bg`, `--bg-elev`, `--fg`, `--fg-muted`, `--accent`
  (single restrained accent, no neon), `--ok`, `--warn`, `--danger`, spacing 4-pt scale, radii 6/10,
  mono font for ids/amounts (system mono stack), sans for text (system stack; no webfont download).
- **Primitives** (`src/lib/components/`): `Hash` (truncated middle, hover full, copy button, link),
  `Amount` (nanoERG → ERG with exact decimals, thousands separators, tooltip raw), `Age` (relative time
  + absolute on hover, live-updating), `Table` (dense rows, sticky header, keyboard row focus),
  `InfiniteList` (cursor pagination, "load more" + auto on scroll, preserves scroll on back),
  `Tabs`, `Badge`, `Panel`, `EmptyState`, `ErrorState` (renders RFC 7807 detail), `Skeleton`.
- **Density**: 13–14px body, 12px mono in tables, 36px rows; whitespace via spacing scale, not larger
  fonts.
- **Accessibility**: contrast ≥ 4.5:1 in both themes, focus rings, all interactive rows reachable by
  keyboard, `aria-live` on the indexed-height badge, reduced-motion respected.

## 5. Data layer

- `src/lib/api/client.ts`: `apiGet<T>(path, params)` with base `/v1`, 10 s timeout, problem-JSON
  error type `ApiError { status, title, detail }`.
- `src/lib/api/types.ts`: TypeScript mirrors of the Rust DTOs (`BlockDto`, `TxDto`, `BoxDto`
  with `rent: RentDto`, `InputDto { id, box }`, `AddressDto`, `RichlistItemDto`, `RentItemDto`,
  `PageDto<T>`, `StatusDto`, `SearchDto`). Amounts stay `string`; `src/lib/format/amount.ts`
  converts with BigInt, never `Number`.
- Queries via `@tanstack/svelte-query`: keys `['block', id]`, `['tx', id]`, …; `staleTime` 30 s for
  entities, 5 s for lists, 2 s for status (polled every 5 s until Plan 3's WebSocket replaces it).
- Prefetch on link hover/focus for block, tx, box, address links.
- Cursor pagination: `useInfiniteQuery` with `getNextPageParam = last.next_cursor`.

## 6. Search classifier (`src/lib/search/classify.ts`)

Pure function `classify(q): { kind: 'height'|'hex32'|'address'|'unknown', value }` with unit tests;
`hex32` triggers `/v1/search`, `height` navigates directly, `address` navigates directly (API 404 →
"address not seen yet"). Global keyboard: `/` focuses search, `Esc` clears, Enter navigates.

## 7. Error handling

- Network/API error → `ErrorState` with the problem-JSON `detail` and a retry button; lists keep
  already-loaded pages.
- Explorer `halted` or lag > 100 → persistent banner "index is behind the node by N blocks"; pages
  still render.
- Unknown route → 404 page with search.

## 8. Build, deploy, ops

- `frontend/package.json` scripts: `dev` (Vite proxy `/v1` → `http://127.0.0.1:18090`), `build`,
  `check` (svelte-check), `test` (vitest), `test:e2e` (playwright with MSW mock API).
- `scripts/deploy_frontend.sh`: build, then `rsync -az --delete build/ root@167.233.240.191:/var/www/explorer/`.
- Caddyfile change: `handle { root * /var/www/explorer; try_files {path} /index.html; file_server }`
  plus long `Cache-Control` for hashed assets under `/_app/`, `no-cache` for `index.html`.
- Bundle budget: ≤ 120 KB gzipped JS for the home route; CI check via `vite-bundle-visualizer` size
  script (fail if exceeded).

## 9. Testing

- Vitest: `classify`, `formatErg` (exact BigInt cases incl. 0, 1 nanoERG, 97,739,924 ERG), `Age`,
  DTO mappers, cursor param handling.
- Playwright (mock API via MSW handlers seeded from the three committed fixture blocks turned into
  DTO JSON): every route renders, search flows (height/tx/box/address/unknown), infinite scroll
  loads a second page, theme toggle persists, keyboard `/` focuses search, error state on 500.
- Manual acceptance against Nuremberg once synced: every page for a real block/tx/box/address.

## 10. Phases

1. **Phase 1 (this spec)**: shell, design system, all routes in §3, deploy script, tests.
2. **Phase 2** (after Plan 2 API): tokens list/detail/holders, template pages, register search.
3. **Phase 3** (after Plan 3 API): WebSocket live blocks/txs, mempool page with fee histogram,
   analytics charts (daily stats, miners, rent history), address balance timeline.
